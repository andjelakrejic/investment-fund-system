IEP - TESTIRANJE MODIFIKACIJE NA ODBRANI


(Provera svih asseta:)
kubectl exec -n investment-fund deployment/investment-database -- mongosh investment --eval "db.assets.find().pretty()"

1. KADA ZAVRSIS MODIFIKACIJU U DIRECTOR SERVISU

Ako si menjala samo Python kod u director servisu:

docker compose -p projekat -f .\compose.yaml build director-service
kubectl rollout restart deployment/director-service -n investment-fund
kubectl rollout status deployment/director-service -n investment-fund --timeout=120s

OBAVEZNO proveri da je novi kod stvarno u podu.

Na primer, ako si dodala funkciju highest_profit:

kubectl exec -n investment-fund deployment/director-service -- grep -n "highest_average_profit_category" /app/director/routes/director.py

Ako vidis svoju novu funkciju, novi kod je u podu.

Ako je ne vidis:

kubectl get pods -n investment-fund

Pronadji ime director poda, pa ga obrisi:

kubectl delete pod -n investment-fund IME_DIRECTOR_PODA

Kubernetes ce napraviti novi pod.

Ponovo proveri:

kubectl exec -n investment-fund deployment/director-service -- grep -n "highest_profit" /app/director/routes/director.py


2. AKO SI MENJALA Voting.sol

Ako modifikacija ukljucuje promenu Solidity ugovora:

.\compile.ps1 -file_path "Voting.sol"

Proveri:

Get-ChildItem .\solidity\output

Treba da postoje:

Voting.abi
Voting.bin

Tek onda build director-a:

docker compose -p projekat -f .\compose.yaml build director-service

Restart:

kubectl rollout restart deployment/director-service -n investment-fund
kubectl rollout status deployment/director-service -n investment-fund --timeout=120s

Proveri da ABI/BIN postoje u Kubernetes podu:

kubectl exec -n investment-fund deployment/director-service -- ls -l /app/solidity/output


3. PORT-FORWARD ZA DIRECTOR

Ako vec nije otvoren, u posebnom terminalu: (PONOVO POKRENI SVAKAKO)

kubectl port-forward -n investment-fund service/director-service 5002:5002

Ostavi taj terminal otvoren.

Director je sada dostupan na:

http://127.0.0.1:5002

7. AKO MODIFIKACIJA TRAZI DIRECTOR TOKEN

Ako nova funkcija ima:

@director_required

onda koristi Postman ili curl.

POSTMAN SA TOKENOM

Method:
GET

URL:
http://127.0.0.1:5002/highest-profit

Authorization:
Bearer Token

Ubaci director access token.

TERMINAL SA TOKENOM

curl.exe http://127.0.0.1:5002/highest-profit `
  -H "Authorization: Bearer TVOJ_DIRECTOR_TOKEN"


8. AKO JE MODIFIKACIJA POST RUTA

Primer:

@director_blueprint.route(
    "/nova-ruta",
    methods=["POST"]
)

U Postmanu:

Method:
POST

URL:
http://127.0.0.1:5002/nova-ruta

Body:
raw
JSON

Primer:

{
  "field1": "value",
  "field2": 10
}

Ako je ruta protected:
Authorization -> Bearer Token -> director token

Primer iz PowerShell-a bez tokena:

curl.exe -X POST `
  http://127.0.0.1:5002/nova-ruta `
  -H "Content-Type: application/json" `
  -d "{\"field1\":\"value\",\"field2\":10}"

Primer sa tokenom:

curl.exe -X POST `
  http://127.0.0.1:5002/nova-ruta `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer TVOJ_DIRECTOR_TOKEN" `
  -d "{\"field1\":\"value\",\"field2\":10}"


9. PROVERA PODATAKA U MONGODB PRE TESTIRANJA MODIFIKACIJE

Ako nova funkcija radi agregaciju nad assets kolekcijom:

kubectl exec -n investment-fund deployment/investment-database -- mongosh investment --eval "db.assets.find().pretty()"

Ako hoces samo broj dokumenata:

kubectl exec -n investment-fund deployment/investment-database -- mongosh investment --eval "db.assets.countDocuments()"

Ako modifikacija ocekuje prodate assete, proveri da dokumenti imaju:
- buying_price
- selling_price


10. UBACIVANJE TEST PODATAKA U MONGODB

Ako hoces brzo da proveris agregaciju nezavisno od gradera:

kubectl exec -n investment-fund deployment/investment-database -- mongosh investment --eval "db.assets.insertMany([{name:'A',buying_price:100,selling_price:180},{name:'B',buying_price:200,selling_price:500}])"

Za highest-profit:

A profit = 80
B profit = 300

Ocekivani rezultat je asset B.

koristi director Bearer token u Postmanu ili curl-u.

16. MINI PODSETNIK

Browser:
- dobar za javni GET
- ne koristi ga za protected rutu sa Bearer tokenom

Postman:
- GET/POST
- JSON body
- Bearer token
- najbolji za rucno testiranje API-ja

curl:
- radi offline
- dobra rezerva ako Postman nije dostupan

Kubernetes log:
- prva stvar koju gledas ako dobijes 500

Rebuild:
docker compose -p projekat -f .\compose.yaml build director-service

Kubernetes restart:
kubectl rollout restart deployment/director-service -n investment-fund

Provera novog koda:
kubectl exec -n investment-fund deployment/director-service -- grep -n "IME_FUNKCIJE" /app/director/routes/director.py

Tek kada vidis novu funkciju unutar poda znas da stvarno testiras novi kod.
