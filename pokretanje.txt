4. PROVERA KUBERNETES RUNTIME-A
Proveri da li kubectl vidi klaster:

kubectl cluster-info
kubectl get nodes -o wide

Proveri koji container runtime koristi Kubernetes:

kubectl get nodes -o jsonpath="{.items[0].status.nodeInfo.containerRuntimeVersion}"

Ako rezultat počinje sa:

containerd://

Kubernetes koristi containerd.

VAŽNO:
Docker image-i i kubeadm/containerd image-i ne moraju da budu u istom skladištu.
Na Windows-u se ne pokreće automatski:

sudo ctr ...

u običnom PowerShell terminalu.

Način importovanja image-a u containerd zavisi od toga kako je računar na odbrani podešen:
- možda Kubernetes već vidi lokalne Docker image-e;
- možda postoji unapred pripremljena komanda ili skripta;
- možda se containerd nalazi u virtuelnoj mašini ili WSL-u;
- možda asistenti daju pristup Kubernetes node-u.

Zato prvo pokušaj normalno Kubernetes pokretanje iz narednih koraka.
Ako se pojavi ErrImageNeverPull, pređi na odeljak 15.

9. PORT-FORWARD – OTVORITI ČETIRI TERMINALA

NodePort vrednosti nisu potrebne za grader jer koristimo port-forward i localhost.

kubectl port-forward -n investment-fund service/authentication-service 5000:5000
kubectl port-forward -n investment-fund service/employee-service 5001:5001
kubectl port-forward -n investment-fund service/director-service 5002:5002
kubectl port-forward -n investment-fund service/blockchain 8545:8545

Kada se prikazuje nešto poput:

Forwarding from 127.0.0.1:5000 -> 5000

port-forward je uspešno pokrenut.

13. PONOVNO POKRETANJE TESTOVA – BRZI RESET

Grader testovi ostavljaju podatke u MySQL-u, MongoDB-u i Redis-u.
Pre ponovnog pokretanja testova očisti stanje.

Očisti Redis:

kubectl exec -n investment-fund deployment/order-storage -- redis-cli FLUSHALL

Očisti MongoDB:

kubectl exec -n investment-fund deployment/investment-database -- mongosh investment --eval "db.dropDatabase()"

Preuzmi MySQL root lozinku:

$MYSQL_PASSWORD = (kubectl exec -n investment-fund deployment/authentication-database -- printenv MYSQL_ROOT_PASSWORD).Trim()

Obriši sve korisnike osim početnog direktora:

kubectl exec -n investment-fund deployment/authentication-database -- mysql -uroot "-p$MYSQL_PASSWORD" -e "USE authentication; DELETE FROM user WHERE role != 'director';"

Posle toga ponovo pokreni željenu pytest komandu.

Ako Authentication servis nakon čišćenja MySQL-a prijavi privremenu grešku konekcije, restartuj ga:

kubectl rollout restart deployment/authentication-service -n investment-fund
kubectl rollout status deployment/authentication-service -n investment-fund --timeout=120s

Posle restartovanja ponovo pokreni Authentication port-forward terminal ako se prekinuo.

15. AKO SE POJAVI ErrImageNeverPull
ErrImageNeverPull znači da Kubernetes containerd ne vidi lokalni image, a u YAML-u je imagePullPolicy podešen na Never.

Najpre proveri koji image nedostaje:

kubectl get pods -n investment-fund
kubectl describe pod -n investment-fund IME_PODA

Na Windows-u napravi tar fajl PowerShell komandom:

docker save -o .\iep-images.tar `
  projekat-authentication-service:latest `
  projekat-employee-service:latest `
  projekat-director-service:latest `
  mysql:8.4 `
  mongo:8 `
  redis:7 `
  trufflesuite/ganache-cli:latest

Proveri da fajl postoji:

dir .\iep-images.tar

IMPORT U CONTAINERD

Import mora da se izvrši u containerd runtime-u Kubernetes node-a.
Tačna komanda zavisi od okruženja na odbrani.

Ako vam asistenti daju Linux/WSL/VM terminal direktno na node-u, komanda može biti:

sudo ctr -n k8s.io images import iep-images.tar

Ako vam daju neku drugu komandu ili skriptu za import, koristi njihovo uputstvo.

Posle uspešnog importa proveri image-e u containerd-u, ako je ctr dostupan:

sudo ctr -n k8s.io images list

Zatim obriši neuspešne podove ili restartuj deployment-e:

kubectl delete pod -n investment-fund POD_KOJI_JE_U_GREŠCI

ili:

kubectl rollout restart deployment/authentication-service -n investment-fund
kubectl rollout restart deployment/employee-service -n investment-fund
kubectl rollout restart deployment/director-service -n investment-fund

Windows PowerShell brisanje lokalnog tar fajla:

Remove-Item .\iep-images.tar

NAPOMENA:
Nemoj unapred računati da će sudo ctr raditi u običnom Windows PowerShell-u.
To je komanda za okruženje u kome je dostupan Kubernetes containerd.
