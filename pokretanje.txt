IEP PROJEKAT

1. POKRETANJE

Otvori PyCharm i Docker Desktop.

U PyCharm terminalu proveri:

docker version
kubectl cluster-info
kubectl get nodes

Uđi u root projekta, gde je compose.yaml.

Dok ima interneta:

docker pull python:3.13
docker pull mysql:8.4
docker pull mongo:8
docker pull redis:7
docker pull trufflesuite/ganache-cli:latest

Build svih servisa:

docker compose -p projekat -f .\compose.yaml build

Provera image-a:

docker images

Treba da postoje:
- projekat-authentication-service:latest
- projekat-employee-service:latest
- projekat-director-service:latest
- mysql:8.4
- mongo:8
- redis:7
- trufflesuite/ganache-cli:latest

Opciona rezerva:

docker save -o .\iep-images.tar `
  projekat-authentication-service:latest `
  projekat-employee-service:latest `
  projekat-director-service:latest `
  mysql:8.4 `
  mongo:8 `
  redis:7 `
  trufflesuite/ganache-cli:latest


2. KUBERNETES

kubectl delete namespace investment-fund --ignore-not-found=true --wait=true

kubectl apply -f .\kubernetes\namespace.yaml

kubectl wait --for=jsonpath='{.status.phase}'=Active namespace/investment-fund --timeout=30s

kubectl apply -f .\kubernetes\

kubectl get pods -n investment-fund -w

Kada svi budu 1/1 Running, pritisni Ctrl+C.

Provera:

kubectl get pods -n investment-fund
kubectl get services -n investment-fund
kubectl get pvc -n investment-fund

Treba da postoje:
- authentication-database
- authentication-service
- investment-database
- order-storage
- blockchain
- director-service
- tri employee-service poda


3. PORT-FORWARD

Otvori četiri odvojena terminala i ostavi ih otvorene.

Terminal 1:

kubectl port-forward -n investment-fund service/authentication-service 5000:5000

Terminal 2:

kubectl port-forward -n investment-fund service/employee-service 5001:5001

Terminal 3:

kubectl port-forward -n investment-fund service/director-service 5002:5002

Terminal 4:

kubectl port-forward -n investment-fund service/blockchain 8545:8545


4. GRADER

U petom terminalu uđi u folder iep_testovi:

cd PUTANJA_DO\iep_testovi

Prvo pokretanje:

python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r .\requirements-pytest.txt
pip install setuptools==80.9.0

Sledeći put samo:

cd PUTANJA_DO\iep_testovi
.\.venv\Scripts\Activate.ps1

Kompletan test:

pytest -q --type all `
  --authentication-url http://127.0.0.1:5000 `
  --jwt-secret development-secret-key-at-least-32-characters `
  --roles-field role `
  --employee-role employee `
  --director-role director `
  --with-authentication `
  --employee-url http://127.0.0.1:5001 `
  --director-url http://127.0.0.1:5002 `
  --with-blockchain `
  --provider-url http://127.0.0.1:8545 `
  --grade-report-file grade_report.json

5. PONOVNO POKRETANJE TESTOVA

Pre ponovnog testiranja očisti podatke.

Redis:

kubectl exec -n investment-fund deployment/order-storage -- redis-cli FLUSHALL

MongoDB:

kubectl exec -n investment-fund deployment/investment-database -- mongosh investment --eval "db.dropDatabase()"

MySQL – ostavi samo direktora:

$MYSQL_PASSWORD = (kubectl exec -n investment-fund deployment/authentication-database -- printenv MYSQL_ROOT_PASSWORD).Trim()

kubectl exec -n investment-fund deployment/authentication-database -- mysql -uroot "-p$MYSQL_PASSWORD" -e "USE authentication; DELETE FROM user WHERE role != 'director';"

Zatim ponovo pokreni pytest.

Brzi reset baza ne zahteva ponovno pokretanje svih port-forward terminala.

8. AKO SE POJAVI ErrImageNeverPull

To znači da Kubernetes ne vidi lokalni image.

Proveri:

kubectl get pods -n investment-fund
kubectl describe pod -n investment-fund IME_PODA

Pošto već imaš iep-images.tar, image-i moraju da se importuju u containerd Kubernetes node-a.

Ako vam asistenti daju Linux/WSL/VM terminal na node-u, moguća komanda je:

sudo ctr -n k8s.io images import iep-images.tar

Tačan način zavisi od njihovog okruženja. U običnom Windows PowerShell-u nemoj nasumično koristiti sudo ctr.


9. VAŽNO

- Ne postoji --with-kubernetes.
- Blockchain se uključuje sa --with-blockchain i --provider-url.
- Authentication se uključuje sa --with-authentication.
- Za završnu proveru koristi --type all.
- Ne pokreći testove više puta bez čišćenja baza.
- Posle brisanja namespace-a sva četiri port-forward terminala moraju ponovo da se pokrenu.
- NodePort ti nije potreban jer koristiš port-forward.
